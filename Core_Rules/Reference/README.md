# Core_Rules/Reference

**Nothing in this directory is a rule, and nothing here is loaded at play.**

The modules beside this directory state conclusions. This directory holds the **arguments behind
them** — the working record of how `core_rules.md` was divided into doctrine, epistemics,
presentation and operating procedure, and why each rule landed where it did.

It exists because conclusions survive a rewrite and arguments do not. A module can say that
persuasion is doctrine; only the record can say it was moved there deliberately, over the
alternative, because a d20 module overriding `contest` would otherwise have deleted four rules that
hold under any system.

## How to read it

**As history, not as instruction.** These documents were written before and during the split, and
they describe a file that no longer exists. Line numbers in them point at `core_rules.md` as it
stood pre-cutover; that file is retired and lives in Git history. They are anchors for locating a
passage in the old structure, not routes to anything live.

Where a document here disagrees with a module, **the module is right.** This is a record of how the
decision was reached, not a second copy of the decision.

## What belongs here later

Provenance for core-rules decisions: why a boundary was drawn, what alternatives were rejected and
on what evidence. Not rules, not templates, not procedure — those have homes already, and a document
that could live in one of them should.

Provenance for the *system modules* and the interface between them lives separately, in
`Game_Systems/Reference/`. The split is by subject rather than by kind, because a reader asking why
a game system adapts the way it does and a reader asking why a rule is doctrine are asking different
questions in different places.
